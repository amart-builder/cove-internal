# Morning Brief engine (v1, as built)

The Morning Arrival used to be a deterministic ranking of yesterday's leftover tasks. The Morning Brief engine replaces that with a real chief-of-staff pass: a goals-aware, progress-aware brief generated by a bounded headless Claude session, consumed by the arrival as presentation and rationale (never as task evidence). Shipped 2026-07-14 on `codex/morning-command-center`; live acceptance passed the same day (artifact `0ccb12dd…`, target 2026-07-14, generated through the real worker lane from a live operator's actual data).

## Shape

1. **Context collector** (`src/lib/day-plan/brief-sources.ts`) is Cove-owned. It resolves, normalizes, and bounds each source, and records a per-source manifest (`as_of`, hash, freshness, coverage, trims).
   - Required: the operator's goals file (`data/brief/goals.md`, or the legacy `<workspace>/brain/GOALS.md`, or `COVE_BRIEF_GOALS_PATH`), the sprint memo (`COVE_BRIEF_SPRINT_MEMO_PATH`), a fresh open-task snapshot via `/api/cove-rest` (default base `http://127.0.0.1:3200`, override `COVE_BRIEF_WEB_BASE`), recent settlement/completion summary.
   - Optional (timeout-bounded, degrade to last-known + age label, never a validity prerequisite): latest email-brief card, per-thread email decision queue, jarvis-memory decisions, seven-day calendar, CRM last-touch, and tasks completed in the previous 48 hours.
   - **`day_dump` (priority 0, first section)**: last night's brain dump in the operator's own words, local `day_dumps` first then the dump relay (`data/dump-relay/latest.json`, written by the dump lane on completion, dropped past 60h). It outranks GOALS and the sprint memo, which are hand-written and go stale; the prompt says the dump wins any disagreement about priorities. Added 2026-07-24 after a dump announcing a new top-three priority reached the ledger but never the brief.
     - **Dump status is never filtered** (fixed 2026-07-29, prompt v14). The collector takes the newest dump by `created_at` whatever its extraction status, because the raw text is the operator's and exists from the moment he saves. Requiring `status = 'succeeded'` raced the dump lane: on 2026-07-29 a closeout moving a client install to Monday was saved at 11:55:17 and finished extracting at 11:56:19, while settlement triggered collection at 11:55:19. The brief silently fell back to the 2026-07-24 dump, marked it `stale` in the manifest, and planned the whole day off it anyway.
     - **Every closeout is prepended with a `CLOSEOUT PROVENANCE` line** (`closeoutTimestampHeader`): when it was saved, which working day it covers, which day the brief is for, and how many working days went by without another one. Facts only, no verdict and no prohibition (a test asserts the line contains no "never"/"do not"). The writer judges the age itself, because a closeout ages unevenly: direction survives a gap, a specific time does not. The mandate gives it that frame instead of a rule.
     - **Freshness is the working-day gap, never elapsed hours** (`closeoutGapWeekdays`). Friday's closeout read Monday morning is ~60 hours old and is still the most recent one that exists; the old 60-hour threshold would have marked the normal Monday case stale every week. Gap 0 (or a closeout dated on/after the target) is `current`; anything else is `stale`, which is a manifest label for the operator, not an instruction to the model.
     - The provenance line leads the section because the character cap trims from the end.
   - **`recent_dumps` (priority 2) and `recent_briefs` (priority 3)**: the previous five *weekdays* of closeouts and of Cove's own past headlines (`previousWeekdays`, weekends skipped because the operator does no structured work on them). `recent_dumps` is the older closeouts under the newest one, read for drift: what he keeps re-deciding, what he quietly stopped mentioning. `recent_briefs` is headlines only and is **explicitly not evidence** in the prompt: its single job is letting the brief notice it has now written the same headline three mornings running, which means the work never moved and is worth naming instead of repeating. Added 2026-07-29.
   - **Goals tail preservation (prompt v14)**: GOALS now has a 20,000-character cap. If it still exceeds that cap, Cove keeps the head, marks the omitted middle, and appends every `## Never ...` section in full. Required sources that arrive but are trimmed are named in one worker error line.
   - **`completed_recently` (priority 6, prompt v14)**: the same task fetch used for the open board now contributes up to 15 tasks marked done in the previous 48 hours. The writer opens with that momentum and cannot recommend those tasks again.
   - **`calendar` (priority 7, prompt v14)**: the live calendar source now covers the target day plus six lookahead days, groups visible events by day, and reports its exact window and event count. Only target-day events schedule today. Later days support prep.
   - Calendar and CRM last-touch are live optional sources. When either integration is unavailable, its manifest coverage remains `missing`, and the writer cannot imply it was checked.
2. **Generation** (`src/lib/claude-execution/brief-commands.ts`, worker brief lane): toolless headless session: `-p --no-session-persistence --tools "" --strict-mcp-config`, own config (default opus / high / $1.50 budget), strict JSON schema output, Claude never writes storage. Context values are injected as JSON string literals with a SOURCE_MANIFEST section. The prompt receives the target local date, plan timezone, and canonical weekday/date label; Cove corrects a contradictory narrative opening before storage. PROMPT_VERSION / SCHEMA_VERSION = 14 / 3.
3. **Storage** (`src/lib/day-plan/brief.ts`, table `day_plan_briefs`): immutable artifacts, unique on (target_local_date, input_hash, prompt_version, schema_version). The input hash is a canonical generation envelope: the exact bounded sections plus target date and timezone, versions, model alias, effort, budget. Selection picks the newest eligible artifact; a late-finishing older generation never clobbers a newer one. Sales-action approve/edit/skip state lives separately in `day_plan_brief_action_states`.
4. **Triggers** (`src/lib/day-plan/brief-triggers.ts`): three, all deduped by the envelope hash and replay-guarded (a replayed settlement/reconciliation result returns early):
   - after Day Settlement **reconciliation** completes (scoped to the current snapshot's pending rows, never global);
   - `com.cove.morning-brief` LaunchAgent one-shot at 7:30 local (`--lane brief`);
   - on-demand backfill when Arrival opens with no eligible artifact (generated in background; arrival never waits).
5. **Consumption** (`morningBriefSyncDecision` in `brief-view.ts`, overlay in `store.ts`): every candidate `taskId` must rehydrate against fresh deterministic candidates; invalid selections are dropped and backfilled. The brief contributes ranking, `why_today`, suggested owner, and `what_claude_can_start` only. No hot-swap into an arrival the user has interacted with. Client brief state is keyed to `plan.briefId`.

## Output contract (strict and deeply validated, nested corruption falls back, never 500s)

- `headline`: the day's single decisive move in one plain sentence. No greeting, no date: the arrival screen prints the date above it, and `stripMorningBriefDateClaim` removes any date claim the writer opens with (warning only when the removed one disagreed with the target).
- `narrativeParagraphs`: the body, two to four paragraphs, rendered one `<p>` each. This is the field that keeps the brief from reading as a wall of text.
- `lensNarrative`: derived, never authored: `headline` plus the paragraphs joined on blank lines. Exports, the date guard, and the deterministic fallback all still speak in one flat string. Pre-schema-3 artifacts carry only this field and are split back into paragraphs on read (`splitNarrativeParagraphs`).
- `existingTaskCandidates` (max 8): `{taskId, whyToday, suggestedOwner, whatClaudeCanStart, evidenceRefs}`; evidence refs validated against collected source ids.
- `watchItems`: never-drop checks with evidence, capped at 5 and ranked by consequence. These print directly under the brief, so an unbounded list is a longer read than the brief itself and gets skimmed past.
- `salesActions`: `{contact, channel, evidenceRefs, draftKind: full|beats_only|pointer|blocked, draftOrBeats, approvalRequired: true}`. Close-friend messages are beats_only by standing rule. Nothing ever auto-sends.

## Invariants

- Fail-open everywhere: a brief failure or corrupt artifact must never block or delay Morning Arrival (single fallback boundary around parse + overlay in `ensureDayPlan`).
- `brief_json` and derived per-item annotations are loopback-only, same gate as `claudeSessionId` (`publicDayPlan` in `public-execution.ts`); keep out of logs.
- Cove remains the source of truth; the model proposes structured output only.
- Briefs run on a dedicated worker lane (single-flight claim via `BEGIN IMMEDIATE`) so they never starve behind long execution runs.

## Ops

- `scripts/install-cove-local.sh` installs both worker plists with `COVE_BRIEF_WEB_BASE=http://127.0.0.1:3200`; the 7:30 one-shot logs to `~/Library/Logs/cove-morning-brief.log` (a clean run writes nothing. An empty log after a kick is normal; check `day_plan_briefs` for the artifact).
- Tests: `tests/day-plan-brief.test.mjs` and `tests/day-plan-brief-sources.test.mjs` cover collector bounding and the manifest, goals tail preservation, completed work, seven-day calendar coverage, the envelope hash, artifact selection, rehydration and backfill, additions isolation, sales schema, fail-open behavior, trigger scoping and replay, closeout freshness, and weekday lookback.
- Context budget is 90,000 chars (`MORNING_BRIEF_TOTAL_MAX_CHARS`), raised from 60k with the lookback: the 2026-07-29 brief already spent 58,469 of 60,000, so new sources would have paid for themselves by trimming the tail off `email_brief` and `settlement_summary` without anyone noticing.
- `data/brief-inputs/` is loopback-private, has the same sensitivity as `cove.db`, and enables prompt-version backtests through `node --import tsx scripts/brief-backtest.mjs <artifact-id | --latest N> [--run]`.

## Deferred (documented decisions, do not build without one)

- Full closed evidence registry (bounded grounding shipped instead: required evidence_refs validated against source ids). JSON-literal fencing prevents delimiter breakout, not semantic injection; toollessness bounds the blast radius.
- Cove onboarding goals interview.
- Moving COVE_DB_PATH and backups outside the Syncthing tree (each machine's DB is now un-synced via .stignore instead).

## Cross-machine relay (v1.1, shipped 2026-07-15)

The 7:30 generation moved to the always-on Mac Mini after the MacBook-asleep failure (2026-07-15 morning: dark-wake froze the run; `worker_interrupted`). Design (see `src/lib/day-plan/brief-relay.ts`):

- **No SQLite is shared between machines.** Each machine's `data/cove.db` is machine-private (ignored in each machine's workspace-root `.stignore`; Syncthing does NOT sync `.stignore` itself, so the block must be maintained on both machines by hand). Transport is write-once JSON files under `data/brief-relay/` (artifacts, `<date>-<host>-<uuid>.json`, checksummed, strictly validated, 1MB cap, sync-conflict names ignored) plus attempt-status files under `data/brief-relay/status/` (queued/running/failed with TTL + 10-min clock-skew clamp) so the other machine can see a generation in flight and hold its backfill.
- **MacBook publishes** `data/source-checkpoint.json` (goals + sprint memo hashes) and `data/settlement-relay/latest.json` (worker tick throttled 5 min + settlement route, gated to the machine where `COVE_BRIEF_REQUIRE_SOURCE_CHECKPOINT` is unset). The **Mini requires** a fresh (<26h) matching checkpoint or it fails closed (`source_checkpoint_mismatch`). It never generates from stale synced sources; MacBook backfill covers.
- **Import** is one transaction (`importMorningBrief`): same-key succeeded → earliest-finished wins with full payload adoption unless a plan already pinned the row; local queued/running → adopt; else insert. Scan/import runs in the worker loop and before ensure + trigger evaluation.
- **Progress reconciliation** follows the same ownership rule. The Mini publishes write-once digest and suggestion envelopes under `data/progress-relay/`. Brief collection reads digest relays when its machine-local SQLite store has none. Only the authoritative MacBook Quiet Current API consumes suggestion envelopes into its machine-local store and writes an immutable receipt; the Mini never rewrites `quiet-current.json`.
  - Project digests now include redacted assistant wrap-ups from the actual Claude Code session transcripts. These are self-reports and need corroboration before `likely_done`. Transcript files never leave the machine, and wrap-up text is redacted before it enters stored evidence or relay files.
- **Late-attach**: `ensureDayPlan` on an existing plan attaches an eligible brief only when brief_id is null, plan proposed, arrival due/opened, all items preselected, and durable `arrival_interacted_at` is null (`brief_attach` ledger event, excluded from settlement human-decision provenance). The client fires a one-shot attach-only ensure on load/visibility and polls at 15s only while a generation is live; attach-only failures are silent no-ops (no ledger growth).
- **Ops**: Mini LaunchAgent `com.cove.morning-brief` (7:30, installed via `install-cove-local.sh --mini`, which refuses to run until the operator confirms the `.stignore` block is on BOTH machines); MacBook's 7:30 one-shot is decommissioned (post-settlement trigger + backfill remain). Mini claude auth lives in the gui launchd domain (SSH shells report "Not logged in" because the Keychain is locked there. That is expected, not breakage).
- Live-accepted 2026-07-15: outbox exported both existing artifacts on first worker start; files synced; Mini imported and correctly deduped instead of regenerating; claude smoke passed in the Mini's launchd context; late-attach delivered the day's brief into the open 2026-07-15 plan (exactly one `brief_attach` event).
